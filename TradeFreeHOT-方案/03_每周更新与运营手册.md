## 一、每周只需做一件事：更新 data.json

整个网站的内容都在一个文件里：**data.json**。改它就等于改网站，页面会在 5 分钟内自动生效。

三种修改方式，按你选的部署方案对应：

| 部署方案 | 每周怎么改 | 耗时 |
|---|---|---|
| GitHub Pages | 浏览器打开 data.json → 铅笔图标 → 改 → Commit | 约 1 分钟 |
| 腾讯云 COS | 上传新的 data.json 覆盖旧文件 | 约 10 秒 |
| Cloudflare Pages | Create deployment → 拖入 data.json → Deploy | 约 1 分钟 |

### 改之前务必先做的一步

**先把原内容复制一份到记事本。** 万一手滑，粘回去就能恢复。（用 GitHub 的话连这步都省了——它有版本历史，随时回滚。）

### 改的时候三条铁律

1. **所有文字必须放在英文双引号里**：`"86 分"` 可以，`“86 分”` 会坏。
2. **每一项之间必须有英文逗号**，但**最后一项不能有逗号**。
3. **中括号 `[ ]` 和大括号 `{ }` 必须成对。** 改完数一下，少了就网页报错。

## 二、五种最常见的改动（附可直接复制的片段）

### 改动 1：新增一家核查机构

放进 `verifiers` 这个方括号里，加在最后一个机构的大括号后面（记得补逗号）：

```json
{
  "name": "XX 机构中文名",
  "nameEn": "XX LEGAL ENTITY S.A.",
  "group": "所属集团",
  "groupNote": "一句话说明",
  "nab": "Accredia",
  "nabCn": "意大利",
  "announced": "2026-10-20",
  "nabDecided": "2026-10-18",
  "entity": "必须与证书／决议上的法律主体完全一致",
  "certNo": "认可编号（查不到就写「未公开」）",
  "standard": "依据标准（查不到就写「决议未载明」）",
  "validFrom": null,
  "validTo": null,
  "scopeGroups": ["I","II","III","IV","V","VI","VII","VIII","L"],
  "scopePending": [],
  "scopeText": "用 NAB 决议／证书的原文口径描述认可范围",
  "route": "由 EU ETS（(EU) 2018/2067）认可范围扩展而来",
  "registry": "未公开",
  "officialListed": false,
  "china": { "v": 1, "t": "中文／本地服务能力说明" },
  "site": "https://机构官网/",
  "srcs": ["发证 NAB 决议名称与日期", "官网公告日期"],
  "note": "范围缺口提示或待核验项",
  "d": { "nab":1, "entity":1, "cert":1, "scope":1, "validity":0, "registry":0, "china":1 },
  "biz": { "price":"未公开", "pricing":"未公开", "area":"可服务区域", "langs":"支持语言", "ob":"OB 联合现场核查能力" },
  "tags": { "sign":"有（…）", "remote":"未公开", "annual":"待向机构确认" },
  "history": [ { "d":"2026-10-20", "t":"本榜首次收录。" } ]
}
```

打分 `d` 里七个键：`nab`、`entity`、`cert`、`scope`、`validity`、`registry`、`china`。取值只有 **1（完整公开）／0.5（间接来源或含糊）／0（未披露）**。总分页面自己算，**不要手写**。

### 改动 2：某家机构的活动组变了

改它的 `scopeGroups`。11 个组的写法固定为：

```
"I","II","III","IV","V","VI","VII","VIII","L","LI","LII"
```

含义：Ⅰ水泥、Ⅱ氢/氨、Ⅲ硝酸、Ⅳ尿素及肥料、Ⅴ烧结矿/生铁/DRI/粗钢、Ⅵ铁合金、Ⅶ未锻轧铝、Ⅷ钢铁及铝制品、L CCUS、LI 进口电力、LII 间接排放。**不要把 ice 三组的罗马数字写错。**

### 改动 3：加一条核查案例

放进 `cases`，加一段：

```json
{
  "d": "2026-10-20",
  "type": "认可里程碑 / NAB 批复 / 客户项目复盘",
  "t": "一句话标题，写事实不写评价",
  "s": "客观经过：谁、什么时候、依据什么、批了什么范围",
  "takeaway": "可复用的判断——读者看完这条能直接拿来用的一句话",
  "tags": ["国家／NAB", "机构", "活动组"],
  "src": "这份信息来自哪里，必须能查回去"
}
```

### 改动 4：加一条实操经验

放进 `tips`：

```json
{
  "stage": "签约前 / 数据准备 / 现场核查 / 报告签发 / 全程",
  "t": "一句话经验",
  "risk": "坑在哪",
  "do": "怎么避",
  "ref": "相关法规依据（没有就删掉这一行）"
}
```

### 改动 5：发一条招标／商机

放进 `bids`：

```json
{
  "n": "项目名称（照抄公告原文）",
  "buyer": "采购方",
  "cat": "产品品类",
  "budget": "公告写了就照抄，没写就空字符串",
  "due": "截止时间",
  "url": "公告原文链接"
}
```

**红线：预算和截止时间如果公告没写，就留空，绝不估算、绝不编造。** 本模块的信任成本极高，一条假信息会让整站失去价值。

## 三、改完怎么验证

1. 打开网址，**看页顶部胶囊**：绿色"已连接线上数据 · 基准日 XXXX"= 成功。
2. 如果还是旧的：等 5 分钟，或按 **Ctrl + F5** 强制刷新，或点页面上的"立即检查更新"。
3. 如果胶囊变黄或页面打不开：说明 data.json 语法坏了——**把之前存到记事本的备份粘回去**，再去细改。最常见的原因是漏了一个逗号或多了一个逗号。

## 四、公众号怎么挂

公众号图文是静态的，**发出去就改不了**。所以原则是：**推文讲变化，网站放全量。**

三条入口：

1. **阅读原文**：每篇推文底部原文链接填网址——最稳，微信不拦。
2. **自定义菜单**：已认证服务号可以在菜单直接挂外链，做成长期入口。
3. **文中二维码**：把网址生成二维码放进正文。

### 每周推文模板（直接套）

> 标题：`【每周一更新】CBAM 核查机构榜单：本周 X 家机构有变化`
>
> 开头：本周榜单有哪些变化（只写变化，不重复全表）
> 中段：本期最该注意的一条（比如某家机构缺哪一组）
> 结尾：**看完整榜单、每家机构的逐组覆盖对照 → 阅读原文**
> 文末：免责声明 + 公众号名（听碳的声音）

## 五、引流转化路径

```
出口企业主看到推文 / 朋友转发
        ↓
点进网址，五个模块免费看（建立专业印象）
        ↓
① 机构榜发现自己可能选错机构 → 焦虑
② 法规库确认要做的动作 → 明确
③ 案例看到别人怎么做的 → 参照
④ 经验知道坑在哪 → 认同
⑤ 商机发现有人在招标 → 兴趣
        ↓
滑到页脚：壹碳数科｜CBAM 碳关税合规服务
        ↓
扫码加企业微信 → 咨询评估
```

**关键：转化入口只有页脚这一个位置。** 正文里不弹窗、不插广告，这样工具感才立得住，客户才不反感。

## 六、合规红线（每次内容上线前对照）

- ❶ 凡二手来源或表述含糊的，必须写"待核验项"，**不能写成结论**。
- ❷ 凡政策法规类内容，**必须能回溯到官方原文链接**。
- ❸ 凡行业经验（模块④），页面已有"非官方文件，不能替代法规"的显著声明，**不要把经验写成"官方规定"**。
- ❹ 凡金额、预算、截止时间，**公告没写就留空**。
- ❺ 发现上一期写错了，**必须在更新日志里发勘误条目**，写清"上期怎么写的／实际是什么／依据哪份文件"。承认错误比掩盖错误更值钱。
