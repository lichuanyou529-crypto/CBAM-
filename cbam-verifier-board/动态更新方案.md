# CBAM 核查机构榜单 · 动态更新方案

## 一、先说清楚：这里的"实时"上限在哪

要做动态更新，先得看上游数据源是什么脾气：

| 数据源 | 形态 | 更新频率 |
|---|---|---|
| 欧委会 DG TAXUD 核查专页 | 人手维护的网页 + PDF | 周级／月级 |
| 《State-of-play CBAM accreditation》 | PDF（无 API） | 周级 |
| ACCREDIA / ESYD 等 NAB | 决议 PDF、认可证书 PDF | 不定期 |
| 各机构官网公告 | 新闻页 | 不定期 |

**没有任何一家提供 API、RSS 或结构化 feed。** 这意味着：

- 秒级／分钟级"实时"在物理上不成立——上游一天之内根本不会变；
- 能做到、也只需要做到的，是 **"上游一变，页面最多 N 分钟内自己变"**；
- 巡检频率建议 **每天一次**，最多不要超过每 6 小时一次（再密只会增加被对方封 IP 的风险，且没有信息增量）。

所以本方案的目标定为：**无人值守的日级巡检 + 前端分钟级自动生效**。

## 二、本次已经改造好的部分（前端已支持动态）

原来：`index.html` 里内嵌一个 `DATA` 对象，改一次数据就要改一次 HTML、重新传一遍文件。
现在：

```
index.html  ──启动时 fetch──▶  data.json （线上唯一数据源）
     │                              │
     │  失败（file:// 打开、文件缺失）│
     └────────▶ 内置快照 EMBEDDED_DATA（兜底，照常显示）
```

页面具体行为：

1. 打开即拉 `data.json?_=时间戳`（绕开一切缓存）；
2. 取到 → 顶部绿色胶囊显示「已连接线上数据 · 基准日 XXXX（XX 生成）」；
3. 取不到 → 黄色胶囊「本地快照（未取到 data.json）」并弹提示，页面照常可用；
4. 之后 **每 5 分钟静默复查一次**；从后台切回页面、断网恢复时也会复查；
5. 发现 `data.json` 版本变化 → 弹「检测到新版本」提示并 **1.5 秒后自动刷新**；
6. 右上角有「立即检查更新」按钮，手动触发。

**要改频率／接口地址**，改 `index.html` 里这两行即可：

```js
var DATA_ENDPOINT = "data.json";      // 将来换成后台 API 地址
var REFRESH_MS    = 5 * 60 * 1000;    // 自动检查间隔，单位毫秒
```

> 关键点：**只要服务器上的 `data.json` 换了，所有正在看页面的人最多 5 分钟内自动看到新版——不用重新部署、不用刷新浏览器、不用改 HTML。**

## 三、三档落地方案（按投入从低到高）

### A 档｜静态托管 + 定时改 JSON　★ 推荐先上这一档

- 把 `cbam-verifier-board/` 推到 GitHub 仓库，开 **GitHub Pages**（Settings → Pages → Deploy from branch → `/root`）；国内访问更稳可选 **Vercel / Netlify / Cloudflare Pages** / 腾讯云 COS 静态网站 / 阿里云 OSS 静态网站，任选其一，都是拖拽即用、免费。
- 每周一 09:00 的自动化（已建）负责调研并改写 `data.json`，然后 `git commit && git push`，托管平台自动重新部署。
- **成本**：0 元。**代价**：仍需 AI 每周跑一次（自动触发，不需你动手）。

### B 档｜每日巡检 + 自动提交（无人值守）★ 第二步做这个

把自动化的频率从"每周一"改成"每天 09:00"，并在改完 `data.json` 后自动提交推送：

```bash
git -C "C:/Users/lichuanyou/WorkBuddy/2026-10-12-12-56-48/cbam-verifier-board" add -A
git -C "..." commit -m "data: 榜单更新 YYYY-MM-DD"
git -C "..." push
```

建议保留一道人工闸门：**无实质变化时只写 changelog、不推送**；**有新机构或勘误时才推送，并在报告里点名**，避免"为了更新而更新"。

### C 档｜Serverless 后端 + 数据库　（现阶段不推荐）

云函数定时抓取 → 入库 → 前端 fetch API。能做，但：

- 上游没有实时源，收益主要是"不用 GitHub Pages"，而不是"更实时"；
- 抓取脚本会因对方网页改版而失效，需要告警与维护；
- 目前 4 家机构、28 家 NAB 的数据量，一个 JSON 文件绰绰有余。

**等到机构数上到几十家、要做历史趋势与订阅推送时，再上后端不迟。**（真要上，`DATA_ENDPOINT` 换成 API 地址即可，前端一行不用改。）

## 四、微信公众号那一侧怎么办

公众号图文是静态快照，**发出来就改不了**（只能改错别字级别的少量文字）。三条路：

1. **推荐**：榜单页作为「阅读原文」／文末卡片链接，推文只讲"本周变化了什么" → 读者点进去永远是最新数据；
2. 公众号自定义菜单挂一个「实时榜单」菜单项，长期入口；
3. 每周推文照发（保留完整表格方便读者直接看），同时在开头注明"完整实时榜单见阅读原文"。

## 五、文件清单与日常命令

```
cbam-verifier-board/
├── index.html              页面（含内置快照兜底，一般不用改）
├── data.json               ★ 唯一数据源，日常只改它
├── tools/
│   ├── extract-data.py     首次从 index.html 导出 data.json（只用一次）
│   ├── embed-snapshot.py   把 data.json 同步回 index.html 内置快照
│   └── smoke-test.js       冒烟测试（需 jsdom）：分别模拟"取到/取不到 data.json"两种情况，
│                           校验渲染结果。用法：
│                           NODE_PATH=<node workspace>/node_modules node tools/smoke-test.js
├── 动态更新方案.md          本文件
├── 部署与更新说明.md
└── 公众号推文_YYYY-MM-DD.md
```

常用命令（用托管 Python，本机 Git Bash 缺 coreutils，别用 bash 内置命令）：

```bash
# 1. 改完 data.json 后，同步内置快照（保证 file:// 双击打开也能看到最新数据）
python tools/embed-snapshot.py

# 2. 本地预览（一定要用 http，file:// 下 fetch 会被浏览器拦截）
python -m http.server 8000 --directory cbam-verifier-board
# 浏览器打开 http://127.0.0.1:8000/index.html
```

## 六、三个容易踩的坑

1. **一定要用 http(s) 打开**。直接双击 `index.html`（file:// 协议），浏览器不允许 fetch 本地 json，页面会回退到内置快照——所以每次改完 data.json，记得跑一次 `embed-snapshot.py`。
2. **CDN 缓存**。页面已经用 `?_=时间戳` + `cache:no-store` 双重绕开；若托管平台仍缓存，把 `DATA_ENDPOINT` 改成带版本号的路径（如 `data.json?v=20261014`）。
3. **数据版本号别漏**。`meta.generatedAt` 是页面判断"有没有新版"的唯一依据，`embed-snapshot.py` 会自动写北京时间戳，不要手改成固定值，否则自动刷新永远不会触发。
