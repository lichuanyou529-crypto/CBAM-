## 二、部署（零门槛，任选其一）

因为整个产品只有 **1 个 HTML 文件**，没有构建步骤、没有外部依赖（不用 CDN、不用 npm），所以：

- **静态托管**：任意 OSS / COS / GitHub Pages / Vercel / Netlify，把 `index.html` 丢进去即可。建议路径放根域名，命名 `index.html`。
- **自有服务器**：Nginx 直接指向该文件目录，无需反向代理。
- **临时演示**：本地双击打开即可完整运行（数据写在 HTML 里，不依赖网络请求）。

### 微信公众号挂载方式

1. **「阅读原文」**：公众号后台编辑图文时，底部「原文链接」填入部署后的 URL。这是当前最稳的做法，微信对未认证/unlisted 域名也不拦截点击。
2. **文中二维码**：把 URL 生成二维码放在正文里。
3. **自定义菜单**：已认证服务号可在菜单直接挂外链。
4. 若希望**推文正文内可点击跳转**，需要公众号**已认证**且域名加入 JS 接口安全域名白名单。

> 提醒：页面在微信内置浏览器中打开时，`position: sticky` 的导航栏在 iOS 微信上偶有抖动，不影响使用。已做移动端适配与 `viewport` 处理。

## 三、每周一怎么更新

**只需改一处。** 打开 `index.html`，找到注释块：

```
/* ▼▼▼ 每周更新区：只需改动下面的 DATA 对象，页面其余部分无需调整 ▼▼▼ */
var DATA = { ... };
/* ▲▲▲ 每周更新区结束 ▲▲▲ */
```

### 每周一看三个地方

| 检查项 | 去哪查 | 改哪里 |
| :--- | :--- | :--- |
| **欧委会官方名录是否录入** | https://taxation-customs.ec.europa.eu/carbon-border-adjustment-mechanism/cbam-verification_en | 若名录上线：`meta.officialListCount` 改为实际数字，并逐家把 `officialListed` 改为 `true` |
| **NAB 受理状态是否有变** | 同上页面的《State-of-play CBAM accreditation》PDF（每月多次刷新） | 改 `nabs[]` 里对应的 `rd` / `tcr` 字段，同时更新 `meta.sopDate` |
| **有无新机构官宣 / 老机构补充披露** | 各 NAB 官网认可名录 + 机构官网 news | 往 `verifiers[]` 加对象，或改已有对象的 `d`、`certNo`、`scopeGroups` 等 |

### 每次更新必改两个字段

```js
meta.dataAsOf      // 本期数据基准日，如 "2026-10-19"
meta.changelog     // 在最前面插入一条：{ d:"2026-10-19", t:"本周变化描述…" }
```

`changelog` 数组**最新的放最上面**，页面会自动渲染成更新日志列表。

### 新增一家机构：照抄这个模板

```js
{
  name:"机构中文名", nameEn:"English Name",
  group:"所属集团", groupNote:"备注",
  nab:"Accredia", nabCn:"意大利",            // 发证 NAB
  announced:"2026-10-20", certDate:null,      // 官宣日 / 证书签发日
  entity:"持证法人全称",
  certNo:null, standard:"未公开",             // 证书编号 / 依据标准
  validFrom:null, validTo:null,               // 有效期起 / 止
  scopeGroups:[],                             // 已获授权的活动组，如 ["V","VI","VIII"]
  scopeText:"公告/证书中关于认可范围的表述",
  registry:"未公开", officialListed:false,
  china:{ v:0, t:"对华服务情况说明" },        // v: 0=无 0.5=部分 1=明确
  site:"https://...",
  srcs:["来源 1","来源 2"],
  note:"<b>核验提示</b>…",                    // 可用 <b> 标签
  d:{ nab:1, cert:0, entity:0, scope:0, validity:0, registry:0, china:0 }  // 7 项披露打分，0/0.5/1
}
```

**打分不用自己算总分**，`scoreOf()` 会自动按权重（15+20+15+20+10+15+5=100）算出指数、百分比与星级，排名也自动重排。

## 四、接后台时怎么改（第二阶段）

现在数据写在 HTML 里。将来做后台，只需要：

1. 后台输出同结构的 JSON；
2. 在 `</body>` 之前加一行引用即可，**页面其余逻辑一行不用动**：

```html
<script src="/data.json" onerror="void 0"></script>
<!-- 或用 fetch： -->
<script>
  fetch('/api/cbam-board').then(r=>r.json()).then(d=>{ window.CBAM_DATA=d; location.reload(); });
</script>
```

因为渲染代码里已经预留了 `var D = window.CBAM_DATA || DATA;`，外部数据会自动覆盖写死的数据。

**建议后台表结构**（对应 DATA 的键即可）：

- `meta`（1 行：dataAsOf / sopDate / officialListCount）
- `verifiers`（主表，7 个披露维度存 `nab_d`/`cert_d`/… 小数）
- `verifier_sources`（来源明细，一对多）
- `verifier_scope`（活动组授权明细，一对多）
- `nabs`（24+ 行）
- `changelog`（按周追加）
- `activity_groups`（11 行，基本静态）

## 六、编辑性建议

- **透明度指数的定位**：这是"信息披露排名"，不是"能力排名"。对外表述务必守住这条边界，否则容易被理解为商业评价，带来不必要争议。已在页脚与免责声明中写明。
- **凡是拿不到一手证书的信息**，在 `note` 里标「待核验项」，反而会成为本榜最值钱的部分——它教读者自己去验，而不是替读者下结论。
- **保持中立**：页面不挂任何机构广告位或联系方式（除机构官网原始链接），避免被质疑"付费上榜"。后续若做「商情版」，建议分出独立栏目，与本榜明确区隔。
